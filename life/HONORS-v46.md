# JUNJA VILLAGE v46 — 업적·장인 칭호·30일 경제 통계
2026-10-19 KST

## 실제로 구현한 기능
- **총 10종 업적:** 공통 3 / 농부 3 / 요리사 2 / 상인 2. 전문 생산 횟수(`business_produce`), 주민 일반·VIP 납품 횟수(`npc_purchase`/`npc_vip_purchase`)를 **실제 서버 영수증**만으로 집계합니다.
- 업적은 단계별 목표와 증빙 실적을 표시합니다. 직업별 해금 조건에 **다른 직업 기록을 더하지 않습니다.**
- **착용 칭호:** 이미 달성한 업적을 골라 선택할 수 있습니다. 칭호 변경은 v36 시험 경제 `state.businessHonorV46.equipped`에 기록하고, 재접속해도 유지됩니다. 골드·XP·아이템 지급 없음. 0G 기록도 v36 영수증과 v37 SHA-256 복구 체크포인트를 **단일 트랜잭션**으로 저장합니다.
- **30일 주민 매출:** 한국 시간 기준 최근 30일간 `npc_purchase`와 `npc_vip_purchase` 판매만 일별·합계로 조회합니다. 거래 수, 실제 받은 금액, 주민 운영세, VIP 서비스료를 구분한 막대 그래프. 구매자 재고, 다른 유저 지갑, 개인 ID 등은 절대 반환하지 않습니다.
- 기존 개인 3D 사업장 메뉴에 추가. 타인의 사업장을 방문하는 게스트 화면에는 칭호 장착·개인 경제 API가 보이지 않음.
- 하루 30개 데이터로 한정, 새 폴링/백그라운드 타이머 불필요.
- 10종 칭호는 명예성 장식이며 **전설 장비·사업 보너스·유료화 재화가 아님**. 신규 서버 경제 골드 생성량 0.
- v36~v45의 독립 시험 경제 내에서만 사용. 기존 운영 레벨·보유금·프로필·`village_saves`·`village_wallets`을 수정하지 않음.

## 보안·제어
- `GET /api/business-honors-v46`: 인증 후 자기 업적과 30일 매출 통계만 조회.
- `POST /api/business-honors-v46`: 본인 세션, 동일 출처, JSON 및 유효 UUID 검사. 기록에서 해금된 칭호인지 재검증 후 착용. 다른 방문자는 타인의 칭호를 지정할 수 없음.
- 요청 재시도: UUID 동일 재요청 7건을 처리해도 단 한 번만 기록하며 새 금액이나 아이템은 전혀 지급되지 않음.
- v37 복구 체인 불일치 시 작성 중단(실제 승인 없이 자동 복구/기록 덮어쓰기 금지).
- `ENABLE_VILLAGE_HONORS_V46=true` 기본 OFF. Neon 시험 데이터베이스를 사용하는 별도 준자마을 스테이징 프로젝트에만 활성화합니다.
- 신규 마이그레이션 없음; 이미 있는 v36 accounts JSONB와 event, v37 체크포인트를 재사용.
