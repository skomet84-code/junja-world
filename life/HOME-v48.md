# JUNJA VILLAGE v48 — 나만의 3D 집 · 인테리어 · 희귀 가구 (시험 경제)
2026-10-19 KST

## 구현
- 기존 운영 캐릭터 `state.home`을 변경하지 않는 **새로운 개인 시험 주택**. v36 서버 경제 JSONB 계정의 별도 필드 `houseV48`만 저장.
- 레벨 1(숲속 작은 집): 4×4칸, 가구 5개까지 배치, 처음부터 원목 의자 1개 무료 제공.
- 레벨 2(햇살 정원 하우스): 8,000G 증축, 5×5칸, 9개 배치.
- 레벨 3(아틀리에 빌라): 30,000G 증축, 6×6칸, 14개 배치.
- 레벨 4(로열 저택): 120,000G 증축, 7×7칸, 20개 배치.
- **가구 9종**: 원목 의자, 티타임 탁자, 몬스테라, 플로어등, 벨벳 소파, 장인의 책장, 희귀 크리스털 조명, 희귀 황금 그랜드피아노, 전설 로열 샹들리에.
- 희귀 구매 해금: **주민 일반/VIP 실제 판매 영수증 3건**(크리스털), **전문 사업장 실제 제작 영수증 8건**(피아노), **판매 8건 + 전문 생산 15건**(샹들리에) 및 충분한 집 레벨.
- 모든 가격은 서버 고정, 골드 지출만, 별도 보상이나 임의 환급·랜덤 뽑기 없음. 등급별 가구 개수 제한, 계정별 보관 개수 제한과 실제 배치 개수 제한.
- 보유 가구는 배치/90° 회전/보관이 가능. 재배치·회전에 추가 골드 차감이나 가구 소실 없음.
- 벽지 4종, 바닥재 4종; 건물 레벨에 따라 잠금 해제. 색상 변경은 명예 인테리어 기능으로 골드 소비가 없고, 기존 집 상태에 저장되지 않음.
- **3D 절차적 실내**: 원목 바닥/창문/벽체/원목 가구/로열 가구 조형은 실제 Three.js 메쉬. 바닥 터치로 배치 칸 선택, 좌우 드래그로 실내 시점 회전. 기존 3D 개인 농장·사업장은 보존됨.
- 기존 '우리집' 메뉴와 '나만의 농장' 메뉴에서 **v48 인테리어 쇼룸 (시험 G)**을 직접 열 수 있음.
- 휴대폰 320/390/430px 하단 메뉴를 건드리지 않고, 인테리어 창만 별도 CSS로 정돈. 7×7 바닥 칸은 터치 44px를 유지하며 선택 표 안에서만 수평 스크롤; 페이지 전체 오버플로 방지.

## 데이터·보안
- API `GET/POST /api/personal-home-v48`, 고유 세션·동일출처 POST JSON 검증, 서버측 행동/아이템 ID 고정 목록 검증, UUID 중복 지급/구매 방지.
- 서버 PostgreSQL 계정 행 잠금 + 가구/골드/배치 상태 + v36 거래 영수증 + v37 SHA-256 복구 체인을 **단일 트랜잭션** 처리. 손상 발견 시 자동 초기화하지 않고 거래 중단.
- 구매 가격·등급·판매 업적·제작 업적·아이템 소유 여부는 **클라이언트가 조작 불가능**하며 반드시 서버 DB 내 영수증을 조회.
- 신규 SQL 마이그레이션 없음; `village_economy_v36_accounts.state.houseV48` 및 기존 v36/v37 영수증 활용. 과거 운영 데이터 `village_saves`, `village_wallets`, `state.home`, 유저 레벨·경험치·기존 어항/가구·HP/MP/행동력 미수정.
- **`ENABLE_VILLAGE_HOME_V48=true`** 기본 OFF; `junja-village-v42-staging`에서만 활성화.

- `test_personal_home_v48.mjs`: 순수 집 레벨·매매·9가구 희귀 조건·재배치/회전·불일치 방지.

- `test_personal_home_browser_v48.mjs`: 실제 모바일 320/390/430px Chromium WebGL 3D 방/가구 구매→배치→회전→증축→희귀 구입, 스크린샷 및 GPU 자원 해제.
- 기존 v32~v47 저장·경제·3D 회귀 테스트 전체 보존.

## 출시 경계
- 이 기능은 **기존 운영 주택에 직접 가구를 배치하는 기능이 아닌 새 서버 시험 주택**. 새 주택과 운영 주택 사이의 골드·가구 자동 이전은 의도적으로 구현하지 않음.
- 실제 iPhone Safari 정식 계정 로그인/2인 플레이/반복 재접속 검증 후 운영 연동 판단 필요.
- 예전에 보고된 레벨 1/5 초기화 이슈의 근본 해결은 별도 작업; 기존 운영 서버 배포·DB 변경 금지.
