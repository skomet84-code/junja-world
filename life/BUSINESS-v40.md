# 준자마을 v40 · 직업별 개인 사업장·전문 생산품·주간 경쟁 (시험판)
2026-10-19 KST

## 구현된 기능
- 직업 숙련도 **2단계(숙련)** 이후 해당 직업의 개인 사업장을 건설할 수 있습니다.
- 농부: 🌿 프리미엄 온실(건설 3,100G) → 🍓 프리미엄 딸기 상자 (딸기 3개 + 가공비 130G)
- 요리사: 🥧 수제 베이커리(건설 4,800G) → 수제 과일 타르트 (사과 1, 밀 2, 딸기 1 + 450G)
- 상인: 🏪 유통 공방(건설 4,000G) → 마을 축제 선물세트 (당근 2, 사과 1, 딸기 1 + 380G)
- 사업장 3단계까지 확장: 전문가 등급부터 2단계, 명장 등급부터 3단계. 가공비 5~10% 절약.
- 한 번에 활성화 가능한 직업은 v39와 마찬가지로 하나. 다른 직업으로 변경해도 이미 건설한 사업장 상태는 남고, 그 직업 재활성화 때 이용할 수 있습니다.
- 직업별 전문 생산품은 기존 v38 주민 상점에서 판매·구매할 수 있도록 서버 물품 카탈로그/화면 연결.
- 새로운 전문 생산은 v39 직업 XP 근거에 합산됩니다.
- 월요일 00:00 KST부터 집계되는 분야별 상위 5명의 **실제 서버 전문 생산 건수** 순위표. 현재 순위는 칭호/골드를 지급하지 않습니다.
- 별도 '나만의 사업장' 메뉴 및 API `/api/business-v40`.

## 안전성 및 데이터 범위
- **v36~v39의 별도 시험 경제 지갑과 창고**만 사용합니다. 기존 운영 플레이어 레벨/골드/의상/마을 저장 데이터는 수정하지 않습니다.
- 건설/확장/생산 때 서버가 직업, 실제 거래 영수증 경력, 골드, 재료, 보유 사업장 등급을 검증합니다.
- 브라우저가 가짜 경험치, 수확 횟수, 가격, 창고 수량을 보내도 서버 상태는 영향을 받지 않습니다.
- 시도한 각 성공 거래는 지갑과 재고, v36 영수증과 v37 SHA-256 연쇄 스냅샷을 **하나의 SQL 트랜잭션**으로 변경합니다.
- 같은 요청 UUID의 동시 재시도는 영수증을 재사용하고 결제/상품 지급을 중복하지 않습니다.
- 서버 계정과 체크포인트가 불일치하면 추가 거래 거부.
- 기능 플래그 `ENABLE_VILLAGE_BUSINESS_V40=true`가 없으면 HTTP 503. **기본 OFF**.
- v40은 기존 v36/37 DB 테이블을 그대로 쓰며 **별도 SQL 마이그레이션은 필요하지 않습니다**.

## 테스트
- `test_business_v40.mjs`: 직업 등급/비용/재료/가공 수량, 사업장 업그레이드, 거래소 제품 카탈로그, KST 주간 집계.
- `test_business_postgres_v40.mjs`: 일회성 로컬 PostgreSQL 17. 로그인/권한, 직업 활동 영수증, 건설 중복 요청 5개/생산 6개, 재고 1회 차감, 주간 랭킹, 구매자 1명이 해당 상품을 주민 거래소를 통해 구매 후 양쪽 장부 무결성 확인.
- 동작하지 않는 거래의 서버 응답은 에러로 처리하고 계정·거래 기록은 변경하지 않습니다.
- PostgreSQL 테스트 파일은 `JUNJA_V40_DISPOSABLE_DB=true`와 localhost:5432 주소가 아니면 실행 거부합니다.
- `npm test`, `npm run build`로 기존 마을 저장/농장/개인 거래와 함께 회귀 검사.

## 개발 상태와 제한
- **현재 사업장 표현은 관리 메뉴와 레벨/상품/성장 데이터**입니다. 맵 위에 건물을 원하는 좌표로 배치하고 건물 안에 들어가는 입체 건축은 아직 미구현입니다.
- 주간 랭킹은 서버 생산 횟수만 집계하며 경제 활동 전체가 실시간 랭킹에 반영된 것은 아닙니다.
- 서버 랭킹은 개인 닉네임 표시를 포함하므로 실제 서비스 공개 전 동의/표시 정책을 검토해야 합니다.
- 별도 Vercel 미리보기/Neon 스테이징 로그인 연동, 실제 iPhone Safari 2인 테스트, 관리자 부정거래 조사 도구, 운영비와 물가 균형 모니터링은 아직 남았습니다.
- **운영 배포와 기존 레벨/재산 이관은 수행하지 않았습니다.**
- 새 코드와 기존 v34~v39는 PR 체인 형태로 누적되므로 실제 출시 전 모든 PR을 함께 검토해야 합니다.
