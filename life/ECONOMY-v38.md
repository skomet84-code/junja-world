# JUNJA VILLAGE v38 — 주민 개인 상점·플레이어 거래소 (시험판)

2026-10-19 (KST)

## 지금 구현된 것
- 기존 주민 계정 로그인 사용, 시험 전용 서버 농장/지갑(v36)과 복구 체크포인트(v37)에만 연결합니다.
- 상추·당근·딸기·밀·사과·딸기잼·사과파이 등 **서버 허가 품목만** 판매할 수 있습니다.
- 판매자가 물건을 등록하면 지정 수량은 **창고에서 즉시 차감해 에스크로(판매 보관)** 처리합니다.
- 다른 주민이 사면 **한 SQL 트랜잭션** 안에서
  구매자 골드 차감 → 구매자 창고 지급 → 판매자 골드 정산 → 판매 상태 변경 →
  양측 거래 영수증 → 양측 v37 복구 스냅샷 생성이 함께 일어납니다.
- 판매자가 판매를 취소하면 보관 수량을 원래 창고로 돌려줍니다.
- 등록 수수료 12G(환불되지 않음), 거래 성사 수수료 5% (올림), 1건 1~20개, 최대 12개 활성 등록.
- 개당 가격은 NPC 기준가의 50~300%만 허용합니다. 이 숫자는 **경제 밸런스 실험값**입니다.
- 서버가 가격·수수료·재고/골드 상한을 검증하고 클라이언트가 정산 금액을 지정하지 못합니다.
- 동일 구매 요청 UUID의 재전송은 과거 완료 결과만 반환; UUID 내용을 바꾸면 거절합니다.
- 본인 상품 구매 금지, 남의 판매 취소 금지, 이미 팔렸거나 취소한 물건 재구매 금지.
- 모든 자산 변경 시 v37 체인 검사. 기존 기록과 다르면 **거래를 중단**하고 관리자 확인을 요구합니다.

## 완성도와 제한
**현재 개발 완료/검증 가능한 것은 서버 거래소 시험판이며, 운영 중인 마을 거래소가 아닙니다.**

- 운영 서버의 기존 레벨·골드·의상·개인 농장 재고를 자동 이전하거나 환전하는 기능이 없습니다.
- v38 기능 스위치 `ENABLE_VILLAGE_MARKET_V38=true` 기본 OFF. 서비스에 새 코드가 배포되더라도 스위치를 별도로 켜지 않으면 거래 불가.
- v36/37 독립 지갑을 사용하므로 라이브 캐릭터 지갑의 안정성이 보장됐다고 주장하지 않습니다.
- 주민 랭킹/세금 사용처/검색·정렬·기간 제한·배송 기능/경매는 미구현.
- 실제 운영 공개 전에는 2기기 iOS Safari QA, 유저 간 권한, 시세 조작 악용, 로그 복구, 데이터 보호, 트래픽·DB 비용 검증 필요.

## 보안·데이터 보호
- v36/37 계정·영수증·복구 스냅샷만 갱신. 기존 `village_saves`, `village_wallets`는 조회하거나 수정하지 않습니다.
- DB 계정 행을 사용자 ID 정렬 순으로 잠가 양방향 거래 데드락 가능성을 줄입니다.
- 판매 등록 때 창고에 없던 물건을 만들거나, 구매자·판매자 수량을 새로 생성하지 않습니다.
- 같은 상품에 경쟁 구매 요청을 보내도 **한 거래만** 완료됩니다.
- 두 계정과 상품 행, 영수증, 복구 스냅샷, 요청 중복 방지 기록을 함께 확정합니다.
- 트랜잭션 실패 시 전부 취소합니다.
- 외부 Origin POST, 타 사용자 판매 취소, 본인 상품 구매를 거부합니다.

## 테스트 결과
- `test_player_market_v38.mjs`: 가상 계정의 재고 보관·시세 상한·판매 수수료·취소 환급·돈 부족 및 창고 상한.
- `test_market_postgres_v38.mjs`: **실제 PostgreSQL 17 컨테이너**에서 로그인된 판매자/구매자 세 계정으로 동시 요청·정산·취소·중복 방지·자산 무결성 확인.
- CI는 오직 `localhost:5432` 임시 테스트 데이터베이스만 허용합니다. 외부 DB가 연결되어 있으면 테스트가 즉시 실패합니다.
- 기존 저장(v32), 경제(v34/36/37), 3D 농장(v35) 회귀 테스트와 브라우저 자산 빌드 포함.
